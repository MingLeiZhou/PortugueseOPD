# 连续快照前端同步

当前快照目录：`public/data/snapshots/index.json`。前端从目录读取数据，不再硬编码三个案例。

| 分组 | 时间范围（UTC） | 数量 | 模型 |
| --- | --- | ---: | --- |
| 代表快照 | 2026 年 1、3、9 月原时刻 | 3 | 原版参考，保留原地图与结果 |
| 夏季连续周 | 2025-07-07 00:15 至 07-13 23:15 | 168 | 接入修订 + 实际有功聚合去重 |
| 冬季连续周 | 2026-01-19 00:15 至 01-25 23:15 | 168 | 同上 |

这些是逐小时独立求解的稳态案例，不是连续动态仿真。规划定额、未证实 GIS 接点隔离等敏感性实验没有混入主快照。

## 使用

左侧面板顶部选择分组、日期和时间；顶部左右箭头在当前分组中前后移动，到达首尾后禁用，不将不同周首尾连接。日期切换尽量保留原小时。顶部高度不变，日期选择没有挤入标题框。

每次只下载所选时点的设备结果和摘要。连续周采用列式 JSON（`schema_version: 2`），避免重复字段名；前端仍兼容原三快照的对象数组格式。风险面板只显示当前时刻的线路、变压器热点，不展示旧的证据范围提示或整日风险数。模型额定值筛查不能解释为实际电网过载。

## 复现同步

在项目仓库根目录执行：

```bash
python portuguese_hv_network/src/export_web_seasonal_snapshots.py --workers 3
```

前提是研究目录 `outputs/temporal_validation/seasonal_revision/` 已有完整的修订模型、资产表、336 条结果和来源清单，且原三快照已导出。若重跑旧版 `export_web_snapshot_data.py`，须随后运行上述命令恢复连续周目录。

导出程序先核验研究来源校验值，再按相同输入复算并对照 10 个原始结果字段，绝对容差为 `1e-5`；不修改论文实验、原基准模型或发布包。逐设备结果在地图 JSON 中保留 6 位小数，摘要保留原始精度。所有时点成功后才更新目录；已完成文件通过指纹和 SHA-256 检查后可复用。

连续周另使用 `generators_revised.geojson`：旧地图中部分顺序编号的资产身份已经变化，不能把修订出力直接拼到旧名称、铭牌和位置上。原三快照继续使用原资产底图。接入母线、容量、投运状态与逐时出力分别保留；未来投运或未映射资产不作为当前在运资产显示。

原始求解网络只保存在本次生成的临时目录，提取结果后自动清理。导出日志、输出校验值和研究指纹保存在 `outputs/temporal_validation/web_seasonal_export/`。生成的前端数据仍遵循现有 `.gitignore`，不是源码提交的一部分。
